# 管理端现场工作台设计

用户已授权按既有路线独立设计、实现、审查与原子提交，无需逐步人工确认。本轮基于已合并影像工作台的主分支 `058df2d`，在 `feat/admin-event-workbench` 开发，不推送、合并或部署。

## 方案与范围

采用独立现场工作台，复用影像工作台的集合草稿与显式应用模式。相比一次实现现场与片段的通用编辑器，这个范围更易验证时间与状态造成的展示变化；相比 JSON 快捷插入，结构化表单可以维护已有记录并保护临时输入。

支持新增、选择、编辑现场记录：只读稳定 ID、双语标题、城市和场馆、带明确时区的日期时间、`scheduled`／`sold-out`／`cancelled` 状态、HTTPS 详情链接和可选图片／GIF 海报。中文必填，英文可清空删除。新记录使用 `event_` 加 UUID，默认 `scheduled`，其余必填字段为空，不编造演出信息。

日期使用 ISO 8601 原文输入，明确显示 `Z` 或 `±HH:MM` 时区提示，不使用隐式本机时区的 `datetime-local`，不归一化或重写合法偏移量。完整 canonical 校验决定可应用性。已有 ID 不允许改名，不提供记录删除、数组重排、上传或媒体播放。

## 事务与展示

`EventDraft` 仅持有深复制的 `events`。打开与应用同步解析当前 `editorText`；应用先精确比较原文基线，再检查当前快照、草稿形状和既有 ID 保留，最后只替换 `events` 并执行完整结构与语义校验。重复 ID、无时区时间、无效日期、非 HTTPS 链接、悬空或错误类型海报均拒绝应用，失败保留原文、输入与可定位诊断。

时间或状态变化可能隐藏现场，进而使现有内部跳转失效，必须由完整语义校验拒绝；不能自动删除跳转或修改首页。新记录应用后再到首页工作台重载并添加引用。记录数组顺序不代表首页顺序。

首页和预览继续只显示快照 `generatedAt` 之后且状态为 `scheduled` 的已编排现场，并遵守板块启用和上限。售罄、取消及过去的记录可保存在快照中，但不自动展示。不修改公开站的 UTC 日期呈现、Schema、Go API 或时间调度机制。

## 界面与交接

沿用深色布局、图标工具按钮、双语字段和可访问标签。海报选项只取最近有效快照中的图片／GIF，不加载媒体。日期提示、状态名称、确认与错误文案均支持中英文。选中记录编辑区按 ID 隔离，切换只改变选择，全部草稿输入继续保留。

现场脏状态加入全局 `formDirty` 与离开保护；未应用时保存、导出、审核、发布、回滚被禁用，预览提示仍显示已应用内容。重载／关闭脏表单需确认，取消保留输入；其他表单应用、JSON 编辑或素材插入使基线过期后禁止覆盖。

导入／载入成功才清理全部工作台，失败保留。保存期间锁定全部现场控件，成功刷新所有已打开的干净草稿基线，修订冲突保留原文及表单。跨四工作台的交接复用页面现有流程，不引入通用状态机重构。

## 验收

TDD 验证独立草稿、唯一 ID、仅更新现场、合法时区原文保留、日期／状态／链接／海报失败、内部目标隐藏、过期基线和忙碌状态。组件与页面测试验证切换保留、可选字段清除、四表单保护、替换失败、保存冲突和成功刷新。

桌面与手机浏览器覆盖新增、应用、加入首页、真实 iframe 预览、状态／时间过滤、导出再导入、双语、键盘和布局。执行前端完整门禁、覆盖率与管理端 E2E。保存 API 拦截只验证契约，不替代真实 Go、OIDC、COS 或 EdgeOne 联调。
