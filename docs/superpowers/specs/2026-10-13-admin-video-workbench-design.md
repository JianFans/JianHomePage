# 管理端影像工作台设计

用户已授权独立规划、实现、验证和原子提交，不要求人工审查中间方案。首页视觉预览已合并，主分支基线为 `39c813e`。本阶段承接内容维护路线，先补齐影像记录，现场与片段表单分别安排。

## 方案与范围

采用独立影像工作台，沿用音乐与首页的临时草稿和显式应用模式。相比把影像、现场、片段一次做成通用编辑器，单一记录类型便于明确字段约束、复用既有组件并独立验证。相比在 JSON 编辑器上增加快捷插入，结构化表单能完整处理已有记录和未应用保护。

支持选择、新增和编辑视频记录：稳定 ID、双语标题、图片／GIF 封面、正整数秒时长、至少一个平台链接、精选，以及可选的视频素材。新 ID 使用 `video_` 前缀与 UUID；不编造有效内容。已有 ID 不可修改，本阶段不删除视频记录、重排记录或删除素材。

首页展示仍由首页工作台中的影像板块决定：先将新记录应用到快照，再重新载入首页编排并添加引用。影像工作台不自动加入板块、不改变排序、启用状态或展示上限。可选视频素材只是现有契约字段，公开站的视频卡片仍通过平台外链打开，不增加内嵌视频播放。

## 事务边界

`editorText` 是唯一可保存源。`VideoDraft` 只包含 `videos`；打开时从当前完整有效快照深复制，不读滞后的防抖分析作为事务基线。

应用先比较当前原文与打开基线，随后检查当前快照、草稿结构与既有 ID 保留，再只替换 `videos` 并执行完整 canonical 结构和语义校验。任何失败都返回原文并保留表单，提供稳定错误代码与精确 JSON Pointer。无关内容、素材和全部板块引用保持不变，不修剪链接或静默删除无效字段。

草稿内可以暂存不完整的新记录，切换选择不会丢失任何记录的未应用输入。重新载入或关闭脏草稿时必须确认；取消确认保持输入。JSON 编辑、其他表单应用或素材插入使基线过期后，禁止应用旧表单；重新载入时保留现有确认流程。

## 界面与页面交接

复用现有双语字段、平台链接字段、深色样式和图标工具按钮。封面只列图片／GIF，可选媒体只列视频；选项使用最近有效快照以保留无效 JSON 期间的表单，实际应用始终检查最新原文。素材上传依然由素材工作台负责，未插入快照的素材不可选择。不在编辑器中加载或自动播放视频。

影像脏状态加入统一 `formDirty`，禁用保存、导出、审核、发布和回滚，并进入预览未应用提示与标准离开保护。导入或载入成功后清理全部工作台；失败保留全部输入。保存期间锁定所有影像控件；保存成功后刷新已打开的干净影像草稿基线，保存冲突则保留原文和表单。

## 验证与边界

TDD 覆盖只替换影像、草稿隔离、稳定 ID、无效时长／链接／素材、跨类型与悬空引用、重复 ID、可选字段清除、过期基线和忙碌状态。页面测试覆盖三工作台相互影响、未应用门禁、导入替换失败、保存成功与冲突。

真实浏览器在桌面和手机验证新增、编辑、应用、首页编排、视觉预览、导出再导入、双语、键盘和溢出，以及保存期间锁定与失败恢复。运行管理端与公开站门禁及覆盖率，不降低阈值。

不修改内容 Schema、Go API、数据库、身份接入、公开站展示或云部署配置。测试中的保存 API 拦截只验证契约，不能替代真实 OIDC、Go 服务与云媒体联调。
