# CMS 导航、版本工作区与公开页优化设计提案

## 1. 状态与目标

用户已认可 CMS 工作区的整体布局与样式，并要求在实现阶段完善 Toast、动效和多种强调色。本文件记录认可的视觉方向与行为边界；对应的 OIDC 会话、版本接口、管理端和公开站实现现已按配套计划推进。本文件中的早期原型记录只描述当时的设计验证，不代表当前交付仍停留在原型。

目标是让「遇健我」管理端成为常见 CMS：编辑人员使用账号密码登录，通过左侧导航进入独立模块，在顶部选择整站内容版本，再编辑、预览和提交审核。日常页面不要求填写 API 地址、Token 或版本 ID。

公开站保留现有低饱和深色风格，仅优化轮播操作区、平台入口重复和回顶位置。

## 2. 方案选择

推荐「左侧模块导航、顶部版本栏、中央内容区」。模块和版本分别负责内容类别与整站快照，用户切换模块时保留版本上下文。

其他方案的限制如下：

- 单页总工作台继续叠加表单，会增加滚动、定位和未应用状态的理解成本。
- 以版本作为一级页面、每个版本重新进入一套导航，会增加跨版本查看同一模块的步骤。

## 3. 登录与系统壳层

### 3.1 登录

管理端提供登录入口和错误反馈，不提供公众注册。账号密码由部署配置的 OIDC 身份提供器托管和验证；CMS 不收集或保存用户密码。登录成功进入内容概览；会话过期进入明确的重新登录流程。

设计阶段使用过独立的「演示登录」，不校验、传输或持久化真实密码。正式实现必须建立服务端认证会话，不能用浏览器模拟状态或固定 Token 代替登录。

认证页面由身份提供器提供，CMS 的登录入口跳转到其品牌化登录页。服务端使用标准 OIDC 授权码与 PKCE 流程、验证回调并建立自身会话；密码不提交给 CMS 或 Token 验证接口。

### 3.2 导航与页面

| 导航 | 中央内容区 |
| --- | --- |
| 概览 | 当前线上版本、当前草稿、最近版本活动和编辑入口 |
| 首页编排 | 宣传位、板块引用、顺序、启用状态和展示上限 |
| 音乐 | 作品列表、搜索及独立作品编辑页 |
| 影像 | 影像列表及独立记录编辑页 |
| 现场 | 现场列表及日期、状态和详情编辑页 |
| 片段 | 图片记录列表及说明、跳转编辑页 |
| 素材库 | 全局素材搜索、筛选、上传及选择 |
| 版本历史 | 历史列表、状态、来源、预览及基于版本新建 |

左侧导航使用一致的线性图标和简短标签，底部保留账户、退出和折叠入口。导航切换展示对应模块，不再把各工作台同时堆在页面上。

素材库是全局资源；选中素材并绑定内容时，修改仍归属于当前草稿版本。素材入库不代表已加入内容版本或已发布。

## 4. 全局版本上下文

版本标签代表整份内容快照，不是模块的独立修订号，也不是线上指针。标签展示版本名称和状态；常驻标签数量受限，其余版本从历史菜单选择。手机使用紧凑选择器。

| 当前版本 | 可执行操作 |
| --- | --- |
| 草稿 | 编辑、保存、预览、提交审核 |
| 审核中 | 只读预览，以及按角色允许的审核操作 |
| 发布中 | 只读预览和发布状态查询 |
| 已发布或历史归档 | 只读预览、基于此版本新建；有权限时另行发起回滚 |

切换标签只改变查看或编辑上下文，不触发发布或回滚。「基于此版本新建」复制来源快照并创建独立草稿，后续编辑不能改变来源版本。来源版本标识保存在版本元数据中，不混入 canonical 内容记录。

存在未保存输入时，切换版本提供「保存并切换」「放弃并切换」「继续编辑」。保存失败保留原版本和全部输入；不能先切换再处理迟到保存响应。切换模块不应静默丢失未保存表单，正式实现需采用统一会话草稿或明确离开保护。

历史版本的预览始终使用该版本快照，显示只读状态；预览不能混入当前草稿或当前线上内容。

## 5. 内容编辑与预览

列表负责查找和选择，记录进入独立编辑页。作品编辑按基本信息、曲目和平台分组，中文字段默认展开，英文作为可展开区域；素材通过选择器绑定。

编辑页明确区分未保存与已保存。普通编辑人员不需要理解内部 JSON 应用步骤；现有表单事务、完整契约校验和乐观锁需要保留，并由统一保存入口组织。JSON 导入、导出和诊断保留为高级工具，不占据默认主工作区。

版本级预览提供桌面、手机及中英文选择。对于未保存草稿，明确预览是否包含当前输入；历史预览与编辑态预览不能共用不明确的数据来源。原型用于验证视觉和交互，不证明已完成服务端保存。

## 6. 视觉与响应式

以石墨灰建立底色、导航、内容面板和输入区域的层次，选中态使用低饱和青灰色。参考色为背景 `#101317`、导航 `#151a20`、面板 `#20262f`、边界 `#3b4553`、正文 `#eef1f5`、次文字 `#a6b0bf` 和强调色 `#9ebdb5`。

普通文字对比度至少为 4.5:1，关键控件和焦点边界清晰。避免卡片套卡片、营销式标题和大面积高饱和装饰。后台保留必要的文字标签，图标不替代无法推断的操作名称。

桌面为固定侧栏与弹性主内容区，平板允许折叠侧栏，手机使用抽屉导航和紧凑版本选择器。表单单列排列，操作目标至少为 44 px，支持键盘与 `prefers-reduced-motion`。

### 6.1 消息提示

临时操作反馈统一使用自实现 Toast，固定在页面右下角，不插入内容区，也不推动页面布局。最多同时显示 3 条，其余按到达顺序排队，每条有独立计时和关闭按钮。普通消息显示 5 秒，错误显示 7 秒；指针悬停、键盘聚焦或页面进入后台时暂停计时，恢复后继续剩余时间。

Toast 使用淡入、短距离滑入与退出动画，关闭后剩余消息平滑补位。消息包含状态图标、简短标题和正文；成功、信息、警告与错误同时通过文字和颜色区分，分别使用礼貌或紧急的辅助技术播报。弹窗内触发的提示保持可见且可以操作，关闭弹窗后已有提示仍然保留。

手机端保留边缘与安全区间距，长内容限制在可滚动的提示区域内。公开预览出现试听 Dock 时，Toast 上移避让。表单错误使用 Toast 说明，同时定位对应输入并设置可访问错误描述；持久的版本状态和未保存保护确认仍留在原有上下文中。

### 6.2 动效

导航、按钮、标签页和列表悬停使用约 160–180 ms 的颜色过渡；模块切换使用约 220 ms 的轻微位移与淡入。菜单、对话框、手机抽屉和轮播文案各有简短入场，作品封面只在悬停时轻微缩放，不添加循环装饰动画。

搜索输入造成列表刷新时不重复触发整页入场。系统开启减少动态效果时，CSS 动画与过渡关闭，程序触发的切页、提示补位和滚动同样遵循该偏好。

### 6.3 强调色

保持石墨灰底色，以小面积的语义强调色增加层次，不增加主题切换。

| 色彩 | 用途 |
| --- | --- |
| 鼠尾草绿 | 保存、成功与线上状态 |
| 雾蓝 | 信息提示、预览与影像、素材模块 |
| 淡紫 | 草稿、历史版本与片段模块 |
| 琥珀色 | 待审核、需注意状态与现场日期 |
| 柔和珊瑚红 | 失败与无效字段 |

模块色主要用于选中导航、图标和标题标记，状态色优先表达实际状态，不把整块内容面板涂成高饱和颜色。

## 7. 公开站的三处优化

### 7.1 轮播操作区

有跳转目标时，跳转按钮在翻页按钮上方，宽度等于两个翻页按钮及中间间距之和，左右边缘对齐。下方翻页区域位置稳定，没有跳转目标时不发生水平漂移。视频播放与静音独立分组，不挤入翻页组。

### 7.2 平台入口与页脚

平台入口集中保留在音乐人板块，页脚收简为品牌、域名和版权。作品的平台链接保持原用途，不在此次去重范围内。

音乐人板块允许停用，正式实现不能因此丢失唯一的平台导航入口：当该板块未渲染时，页脚可提供一次站点级平台入口；板块实际展示时页脚不重复。需明确保留 `artist.platformLinks` 与 `site.socialLinks` 的字段职责，不在视觉修改中擅自删除 Schema 字段。

### 7.3 回顶

回顶放在固定顶部导航末端，滚动超过约 480 px 后显示，返回顶部后隐藏。为按钮预留位置，避免导航跳动；手机不得挤走语言按钮。该位置避开底部单实例试听 Dock，不遮挡正文。减少动态效果偏好开启时使用即时滚动。

## 8. 实现边界

CMS 实现使用服务端 OIDC 会话与版本摘要、来源元数据；前端不能把模拟登录、浏览器数组或手动输入版本 ID 当成正式能力。真实 OIDC 提供器、PostgreSQL、对象存储和 EdgeOne 环境配置属于部署验证，代码实现与本地测试通过不代表这些云集成已验证。

实现继续复用 Nuxt、Vue、Go、canonical Schema、已有表单事务和提供器接口。公开站继续只使用构建时快照，不增加浏览器运行时内容 API。

## 9. 设计验收

- OIDC 登录入口、回调与退出使用服务端会话；CMS 不收集或保存用户密码。
- 左侧导航真实切换模块，选中态和页面标题一致。
- 切换模块保持当前版本；历史版本只读，基于历史新建后得到独立草稿。
- 修改后切版本有未保存保护，取消不丢输入；保存后能看到状态变化。
- 音乐列表、编辑、素材选择、保存和预览可连续操作。
- 公开页的跳转与翻页对齐，平台入口没有无意义重复，回顶按滚动阈值显示。
- 桌面与手机尺寸下没有横向溢出，弹窗可关闭，关键按钮有可访问名称。
- 连续触发消息时保持独立堆叠，超过 3 条后排队；关闭、暂停和恢复计时互不干扰。
- Toast 不受切页与弹窗层级影响，并在试听时避开播放器；减少动态效果偏好下关闭动效。

实现验收覆盖认证失效、RBAC、保存冲突、版本分页、来源不存在和发布幂等。真实 OIDC 提供器、PostgreSQL、对象存储及 EdgeOne 集成需在部署环境另行验证。

## 10. 可视化交付与检查记录

Local Codex 设计项目为「遇健我 CMS 版本工作区重设计」，入口文件为 `yujian-studio.html`。原型与本地素材副本保存在独立设计项目中，不属于生产静态产物。

本轮通过浏览器验证了演示登录、七个模块的导航、音乐编辑、未保存时保存并切换、历史只读和基于历史新建草稿。新草稿保持来源内容，当前线上版本不因查看或新建而改变。

在 1440 px 桌面和 390 px 手机视口下，检查的模块页面没有横向溢出。公开预览的跳转按钮与翻页组等宽对齐，切换无目标轮播项时翻页组不移位；页脚未重复平台链接，滚动后回顶按阈值出现。原型页面未出现控制台警告或错误。

手机端「新建版本」隐藏文字后缺少可访问名称的问题已复现并修正；同一浏览器检查在修改前失败、修改后通过。以上记录只说明设计原型的核心交互已检查，不代表生产认证、服务端保存、发布或完整无障碍审计已完成。

本轮消息检查先复现了旧提示覆盖前一条、位于底部中央且无法关闭的问题。更新后，浏览器验证了 3 条堆叠、额外消息排队、独立计时、悬停与聚焦暂停、切页保留、退出动画和手动关闭。

独立设计项目中的 `verify-interactions.cjs` 使用仓库管理端的 Playwright 与本机 Chrome，可在仓库根目录执行。其检查覆盖登录错误 Toast、队列补位、弹窗内关闭、无效字段、390 px 手机边界、试听 Dock 避让以及真实减少动态效果模拟，运行通过且没有页面脚本错误。原型 JavaScript 语法检查通过；上述验证不替代生产应用的单元测试和 E2E 门禁。
