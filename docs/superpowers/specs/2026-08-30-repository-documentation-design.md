# 仓库说明文档设计

## 目标

重写根目录的 `README.md` 与 `AGENTS.md`，让人工维护者和编码代理都能从仓库事实出发完成开发、验证和上线准备，不依赖当前会话上下文。

## 读者与职责

### README.md

面向开发、运维和内容维护人员，回答以下问题：

- 「遇健我」是什么，当前实现到什么范围。
- 公开站、管理端、Go 服务和内容快照如何协作。
- 如何安装、开发、测试和生成静态产物。
- EdgeOne、PostgreSQL、OIDC 与对象存储上线前需要什么。
- 哪些能力不在当前版本范围内，以及详细文档在哪里。

README 只保留稳定入口信息。环境变量全集、API 示例和缓存策略继续由专项文档维护，避免重复。

### AGENTS.md

面向在仓库中工作的编码代理，规定以下可执行约束：

- 开始工作前读取上下文、检查 Git 状态，并优先使用 CodeGraph。
- 根据任务调用适用 Skills，创造性工作先设计，行为修改遵循 TDD。
- 维护内容 Schema、生成文件、静态快照和服务商抽象边界。
- 按影响范围运行测试、类型检查、静态生成和生产门禁。
- 使用中文 Conventional Commits 创建原子提交。
- 代码审查以缺陷、风险、回归和测试缺口为主。
- 未经真实云环境验证，不宣称已经上线。

## 内容边界

- 不在根 README 复制 `apps/server/README.md` 的完整变量表。
- 不在根 README 复制 `apps/web/EDGEONE.md` 的缓存和路由细节。
- 不把临时机器状态、凭据或服务商账号信息写入仓库。
- 不改变代码、构建脚本、运行时行为或现有架构。

## 验证标准

- 文档中的命令必须存在于当前 `package.json` 或模块配置中。
- 路径、技术栈和部署约束必须与当前代码一致。
- Markdown 标题层级连续，代码块带语言标识。
- 不包含 `TODO`、待定内容、秘密信息或无法验证的上线声明。
- `git diff --check`、文档链接检查和项目完整门禁通过。
