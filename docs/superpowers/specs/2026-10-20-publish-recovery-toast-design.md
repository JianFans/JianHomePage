# 发布反馈、恢复与 Toast 修复设计

## 意图与已验证问题

真实部署暴露出：管理端只显示 `building`，刷新页面会丢失任务；提交前的项目查询失败也会进入不确定状态；更改地域后，确认未创建部署也被目标一致性检查阻止；失败任务和恢复接口没有界面入口。配置未充分区分 API 站点与部署区域，脱敏日志隐藏了迁移上下文。Toast 的 FIFO 等待队列延迟新消息，可滚动容器在平移动画时出现滚动条。

用户授权独立制定目标并实施。以下细节为本次实现决定。

## 发布

- 保留现有发布任务状态与 worker 数据库锁、不可变快照、冻结目标和幂等约束。
- 最新任务可在重新进入后台后读取。响应补充持久化构建阶段及安全诊断，普通发布者不获得恢复权限。
- 界面自动轮询，区分排队、生成页面、提交云端、云端部署、完成、失败、需要核实和配置不匹配；轮询不触发新部署，不逐次弹 Toast，不锁定其他内容编辑。
- Pages 适配器显式区分创建部署前失败和创建已尝试。前者结束任务、释放发布位置，允许使用新幂等键重试；后者保持不确定状态，不自动重试。
- 管理员可以填写核实说明，选择绑定已创建部署或确认未创建。绑定仍须当前冻结目标一致；确认未创建仅结束旧任务，允许配置已更改，保留审计与锁。
- 失败后重试创建新任务、保留旧记录，沿用服务端审核规则；回滚重试保持原操作类型。
- 诊断只保留白名单 action/code、HTTP 状态及安全 request ID，不输出云端原文、Cookie 或密钥。

## Toast

- 保留最多三条可见提示，新消息立即出现并淘汰最旧消息，不保存等待队列。
- 淘汰时清理计时器，旧动画事件不得影响新消息；保留指针、焦点、页面隐藏暂停与卸载清理。
- 容器不设置滚动条、固定高度或动画期间的绝对宽度补偿；消息自然换行，宽度受视口安全边距约束。
- 使用不改变滚动尺寸的淡入与轻微纵向动画，支持减少动态效果、键盘关闭和安全文本渲染。

## 配置与边界

明确 `PAGES_REGION` 为中国站 `china` 或国际站 `global`，与项目部署范围、COS 地域不同；Token、项目与 API 站点必须对应。同步 `.env.example` 与部署、服务端文档。保留单 Go 程序架构，不触发真实云端发布，不清理生产数据。

## 验收

Go 覆盖提交前失败、不确定创建不重试、配置变化后的确认未创建、绑定目标保护和最新任务读取。管理端覆盖阶段展示、自动轮询生命周期、重新载入恢复、重试幂等键、恢复权限和失败保留输入。Toast 覆盖新消息替换、计时与暂停，以及真实桌面／手机动画无滚动条。最后执行模块测试、类型检查、Go 门禁和真实浏览器验证。
