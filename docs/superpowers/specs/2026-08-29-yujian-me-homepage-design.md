# 「遇健我」官方站首页设计规格

## 1. 文档信息

- **项目名称：** 遇健我
- **站点域名：** `yujian.me`
- **音乐人：** 王子健
- **文档状态：** 已完成产品方向确认，等待书面规格复核
- **日期：** 2026-08-29

## 2. 项目目标

「遇健我」是音乐人王子健的官方站。首版以只读展示为核心，让访客快速完成以下任务：

1. 认识王子健并形成清晰的品牌印象。
2. 发现最新音乐、影像和现场信息。
3. 在获得授权时直接试听作品。
4. 前往 QQ 音乐、网易云音乐、微博、哔哩哔哩和抖音等官方平台。

公开站必须优先保证加载速度、可访问性和内容稳定性。已经发布的页面不依赖 Go 服务在线，也不在访客访问时抓取第三方平台页面。

## 3. 首版范围

### 3.1 包含内容

- 完整的响应式官方首页。
- 可配置的大封面媒体位，支持图片、动图和视频。
- 音乐、影像、现场、片段、音乐人简介和官方平台板块。
- 可选的站内音频试听与底部迷你播放器。
- 简体中文和英文界面。
- 结构化内容契约与版本化静态快照。
- Nuxt 静态构建和 EdgeOne Pages 发布链路。
- Vue 管理端与 Go 内容服务的基础架构、内容管理和发布流程。
- 管理端预览、发布状态和历史版本回滚。

### 3.2 暂不包含

- 访客注册、登录、评论、收藏或其他写操作。
- 论坛、社区和统一身份中心。
- 票务交易、会员、支付和邮件订阅。
- 运行时抓取 QQ 音乐、网易云音乐或社交平台内容。
- 完全自由的拖拽式页面编辑器。

未来论坛等子站使用统一身份认证（Single Sign-On，SSO）。首版只在数据结构和导航模型中预留入口，不展示登录按钮或空子站导航。

## 4. 视觉方向

### 4.1 基本气质

- 整体采用深色、低饱和视觉，不提供深浅色切换。
- 主色为近黑、雾灰和柔和白，辅以灰蓝与少量暖铜。
- 不使用荧光色、大面积渐变、装饰性光球或高饱和紫色。
- 以官方人物影像和作品封面建立视觉层次，减少装饰性容器。
- 使用自由、错落的媒体构图，避免把首页做成规整的控制台或卡片墙。

### 4.2 文字与图标

- 首屏只保留「遇健我」「王子健」、作品名等必要文字。
- 音乐、影像、现场、语言、播放、静音和平台操作优先使用 Lucide 图标或平台官方图标。
- 不熟悉的图标必须提供 Tooltip、`aria-label` 和键盘焦点状态。
- 移动端没有悬浮状态，播放等关键操作必须始终可见。
- 不用界面文案解释功能、快捷键或操作方法。

### 4.3 媒体原则

- 最终站点使用经过授权的真实人物照片、作品封面和现场影像。
- 设计阶段的色块和示例文案不代表官方事实，不进入生产内容。
- 后台必须记录素材来源、版权说明和署名要求。
- 视频默认静音，可暂停；系统启用「减少动态效果」时使用静态海报。
- 首屏视频在海报和关键静态资源完成后再加载，不阻塞最大内容绘制。

## 5. 首页信息架构

首页默认按照以下顺序展示。每个板块均可在后台独立启用、隐藏、排序和限制数量。

### 5.1 大封面

- 首屏以王子健的官方影像为第一视觉信号。
- 支持图片、动图和静音视频轮播。
- 每个轮播项可配置内部内容引用或外部跳转链接。
- 同一时间只突出 1 条主宣传内容。
- 提供轮播进度、暂停和静音图标。
- 移动端使用独立裁切资源或焦点位置，避免人物和文字互相遮挡。

### 5.2 音乐

- 首页展示最新作品封面序列，并提供「全部音乐」入口。
- 桌面端悬浮或键盘聚焦封面时显示播放按钮。
- 移动端播放按钮始终可见。
- 作品存在授权试听文件时启动站内播放器。
- 没有试听文件时不展示无效播放按钮，仅显示平台入口。
- QQ 音乐、网易云音乐等平台按钮位于作品操作区；窄屏可收进平台菜单。

### 5.3 影像

- 使用 1 条主影像和若干次级影像形成不对称布局。
- 支持站内媒体、哔哩哔哩和其他已登记平台的跳转链接。
- 首页不自动加载第三方嵌入播放器，点击后再按配置打开详情页或外部平台。

### 5.4 现场

- 展示日期、城市、场地和详情链接。
- 没有未来场次时隐藏整个板块，不显示空状态卡片。
- 已结束场次进入历史列表，不占用首页默认位置。

### 5.5 片段

- 展示幕后照片、排练、旅行或创作片段。
- 以图片和短视频为主，说明文字可选且保持简短。
- 不直接抓取微博、哔哩哔哩或抖音信息流。

### 5.6 音乐人信息

- 使用官方肖像、精简简介和平台图标。
- 详细履历进入独立「关于」页面，首页不承载长文。

### 5.7 页脚

- 展示品牌、域名、版权年份和必要的备案或法律链接。
- 未来子站入口只在真实子站上线后显示。

## 6. 播放体验

- 播放器只在用户主动播放后出现，不预占首屏空间。
- 播放器包含封面、播放/暂停、上一首、下一首、进度和关闭操作。
- 页面内切换板块不会中断播放。
- 同一时间只允许 1 个音频实例播放。
- 支持 HTTP Range 请求，试听资源通过 CDN 分发。
- 切换曲目、切换语言或关闭播放器时不造成布局跳动。
- 音频加载失败时保留作品信息和平台入口，并提供简短、非阻断错误提示。

## 7. 国际化

- 默认语言为简体中文，第二语言为英文。
- 不使用语言 URL 前缀，不为语言切换修改路径。
- 首次访问按照以下顺序决定语言：
  1. 读取 `localStorage` 中的用户偏好。
  2. 使用 `navigator.languages` 和 `navigator.language` 匹配支持语言。
  3. 获取失败或无法匹配时回退简体中文。
- 自动选择非默认语言时显示一次非阻断提示。
- 用户手动切换后立即写入 `localStorage`。
- 内容字段缺少英文版本时回退简体中文，界面控件不能出现空白。
- 初始 HTML 和主要 SEO 元数据使用简体中文。英文内容无法单独分享链接，也不作为独立搜索入口；这是明确接受的取舍。

## 8. 技术架构

### 8.1 技术选型

- **公开站：** Nuxt、Vue 3、TypeScript，使用静态生成模式。
- **管理端：** Vue 3、Vite、TypeScript。
- **内容服务：** Go。
- **数据库：** PostgreSQL。
- **对象存储：** 通过 Go `BlobStore` 接口适配具体服务商。
- **静态托管：** EdgeOne Pages。
- **动态入口：** EdgeOne 代理到 Go 服务。
- **工作区：** pnpm workspace；Go 保持独立 module。

### 8.2 仓库结构

```text
apps/
  web/        Nuxt 公开站
  admin/      Vue 管理端
  server/     Go 内容与发布服务
packages/
  schema/     JSON Schema、OpenAPI 与生成类型
  ui/         仅共享真正通用的前端基础组件
content/
  fixtures/   开发和测试内容
  snapshots/  本地构建快照
docs/
  architecture/
  operations/
```

公开站、管理端和服务端通过版本化契约通信，不共享业务实现。

### 8.3 服务商适配

Go 服务定义以下边界：

- `BlobStore`：上传、读取、删除和签名 URL。
- `BuildTrigger`：触发静态构建并查询状态。
- `Notifier`：可选的发布结果通知。
- `IdentityProvider`：首版管理人员登录，未来可替换为统一 OIDC。

业务模型不存储腾讯云专有对象。资源记录只保存稳定 ID、逻辑用途和可迁移元数据。

## 9. 内容模型

系统使用固定内容类型和有限布局变体，不提供任意 CSS 或脚本注入。

| 类型 | 用途 | 关键字段 |
| --- | --- | --- |
| `SiteConfig` | 全站配置 | 品牌、默认语言、SEO、社交平台、导航 |
| `Homepage` | 首页编排 | 有序板块、启用状态、布局变体、内容引用 |
| `HeroSlide` | 大封面 | 媒体、移动端媒体、海报、跳转目标、展示时段 |
| `Release` | 单曲、EP、专辑 | 类型、封面、发行时间、曲目、制作信息 |
| `Track` | 单曲目 | 试听资源、时长、平台链接、制作人员 |
| `Video` | 影像 | 封面、媒体源、时长、平台链接、精选状态 |
| `Event` | 现场活动 | 时间、城市、场地、状态、详情链接 |
| `Moment` | 图片或短视频片段 | 媒体、可选说明、关联链接 |
| `ArtistProfile` | 音乐人信息 | 简介、肖像、官方账号 |
| `Asset` | 资源清单 | 类型、变体、尺寸、校验值、替代文本、版权信息 |

可翻译字段使用语言映射。平台链接引用内置平台注册表，管理员配置 URL，不单独上传平台按钮。

## 10. 静态快照

每次发布生成不可变快照，至少包含以下字段：

```json
{
  "schemaVersion": "1.0.0",
  "releaseId": "rel_20260829_example",
  "generatedAt": "2026-08-29T10:00:00Z",
  "site": {},
  "homepage": {},
  "releases": [],
  "tracks": [],
  "videos": [],
  "events": [],
  "moments": [],
  "assets": []
}
```

构建任务只读取指定 `releaseId` 的快照。相同快照必须可以重复构建出等价站点。

## 11. 管理与发布流程

### 11.1 内容状态

内容状态包括 `draft`、`in_review`、`published` 和 `archived`。草稿修改使用乐观锁，避免多人覆盖。

### 11.2 发布步骤

1. 冻结当前草稿版本。
2. 校验 JSON Schema、关联内容、链接、资源和国际化回退。
3. 生成不可变快照并计算校验值。
4. 通过 `BuildTrigger` 触发 EdgeOne Pages 构建。
5. 对预览或部署结果执行冒烟检查。
6. 记录成功版本、构建信息和操作人。

校验或构建失败时继续提供上一成功版本，不更新当前发布指针。回滚通过重新构建历史快照完成。

### 11.3 权限

管理端至少区分以下角色：

- `editor`：编辑草稿和上传素材。
- `reviewer`：提交或退回审核。
- `publisher`：发布和回滚。
- `admin`：管理人员与系统配置。

本地开发可以启用显式的开发身份，生产环境禁止开发身份并要求 OIDC。

## 12. 错误与降级

- 图片加载失败时使用与版式匹配的本地占位，不改变稳定尺寸。
- 视频不可用时使用海报；海报不可用时隐藏视频控制。
- 试听不可用时隐藏播放入口，保留平台跳转。
- 第三方平台链接失效不影响站内内容展示。
- 内容快照校验失败时构建直接失败，不发布部分页面。
- Go 服务、数据库或管理端不可用时，当前静态站继续访问。
- 管理端发布操作必须具备幂等键，重复请求不能创建多个逻辑版本。
- 外部链接只允许 `https`，并使用安全的新窗口属性。

## 13. 响应式与可访问性

- 关键断点由内容拥挤程度决定，不依赖特定设备型号。
- 固定格式媒体使用稳定的 `aspect-ratio`，防止加载时跳动。
- 移动端不依赖悬浮交互，触控目标不小于 44 × 44 CSS px。
- 文本和交互元素不得遮挡人物、作品封面或彼此重叠。
- 图标按钮提供可访问名称、Tooltip、键盘操作和明显焦点。
- 色彩对比满足 WCAG 2.2 AA。
- 音频和视频支持暂停；自动运动尊重 `prefers-reduced-motion`。
- 语义结构使用 `header`、`nav`、`main`、`section`、`article` 和 `footer`。

## 14. 性能目标

- 公开站不需要运行时内容 API 才能完成首屏渲染。
- 关键图片提供 AVIF、WebP 和兼容格式，并按视口选择尺寸。
- 非首屏图片和视频延迟加载。
- 音频代码和资源在首次播放意图后加载。
- 首屏视频先显示海报，再根据网络和用户设置决定是否加载。
- 生产目标为移动端第 75 百分位 LCP 不超过 2.5 秒，CLS 不超过 0.1。
- 构建产物必须通过预算检查，避免播放器、轮播或图标库进入不必要的首屏包。

## 15. SEO 与 Agent 友好

- 默认中文页面提供规范 URL、Open Graph、站点地图和 `robots.txt`。
- 使用 JSON-LD 描述音乐人、音乐作品、影像和活动。
- 提供稳定的内容 ID、明确的发布时间和平台链接。
- JSON Schema、OpenAPI、示例快照和生成类型纳入版本控制。
- 仓库提供 `AGENTS.md`，说明目录职责、常用命令、验证方式和不可手工修改的生成文件。
- 模块保持单一职责，复杂播放器、国际化、内容加载和发布编排分别测试。

## 16. 安全要求

- 管理 API 使用 OIDC Bearer Token 和基于角色的访问控制（Role-Based Access Control，RBAC）。
- 上传使用短时签名 URL，并校验文件类型、大小、扩展名和媒体元数据。
- 禁止后台输入任意 HTML、脚本或 CSS。
- 管理端与公开站配置内容安全策略（Content Security Policy，CSP）。
- 发布、回滚、人员权限和资源删除写入审计日志。
- 密钥只通过环境变量或密钥服务提供，不进入仓库和静态快照。

## 17. 验证策略

### 17.1 契约

- JSON Schema 示例与反例测试。
- TypeScript 和 Go 生成类型的一致性检查。
- 历史快照兼容性测试。

### 17.2 公开站

- 使用 Vitest 测试内容回退、国际化、播放器状态和板块显隐。
- 使用 Playwright 验证桌面和移动端主要流程。
- 截图检查首页长页、首屏裁切、图标 Tooltip 和迷你播放器。
- 使用自动化可访问性检查并补充键盘测试。
- 验证静态产物在 Go 服务关闭时仍可访问。

### 17.3 管理端与服务端

- Go 单元测试覆盖校验、权限、发布幂等和回滚。
- PostgreSQL 集成测试覆盖事务、乐观锁和审计记录。
- 管理端组件测试覆盖表单、预览和发布状态。
- 端到端测试覆盖「编辑 → 审核 → 发布 → 静态构建 → 回滚」。

## 18. 验收标准

- 首页在桌面和移动端完整呈现已确认的低饱和视觉方向。
- 所有板块可以通过快照独立启用、隐藏、排序和替换内容。
- 图片、视频和音频均有明确的加载与失败降级。
- 语言自动检测、回退、提示和持久化符合本规格。
- 带试听和不带试听的作品都具有正确交互。
- 发布失败不会影响上一成功版本。
- 静态站可以部署到 EdgeOne Pages，动态服务可通过 EdgeOne 代理。
- 服务商适配层允许替换存储和构建触发服务。
- 测试、类型检查、静态构建和 Go 测试全部通过。
