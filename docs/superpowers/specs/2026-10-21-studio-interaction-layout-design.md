# 管理端交互布局优化

## 意图与范围

让编辑者进入模块后知道正在编辑什么、属于哪个版本，以及下一步能做什么。用户授权本轮独立设计和实现；以下布局选择由实现者决定。本轮只调整管理端，公开站保留已认可的设计，不修改服务端、权限或发布契约。

## 布局决定

- 顶栏保留模块路径、语言、公开站入口、预览与保存；滚动长表单时顶栏保持可见。只固定这一行，短屏不被多层吸顶栏占据。
- 顶部版本选项卡继续负责切换历史快照和基于当前版本新建草稿。其后放置当前版本名称、状态、修订与保存状态，构成明确的版本上下文。
- 当前版本的审核／发布动作移到版本上下文内，各模块均可使用。草稿提供提交审核；待审核提供审核入口；审核通过提供发布；已发布和已归档版本提供原有回滚入口。仅显示当前状态和角色对应的动作，忙碌或未保存时沿用现有禁用条件。发布和回滚仍需确认。
- 正文一级标题显示模块名称，版本名称不再占据模块标题。快照工具仍是正文标题旁的次要操作。
- 概览删除重复的版本名大卡片，改为简短引导、内容摘要与快捷入口，保留发布监控和最近版本。历史页专注版本浏览与发布监控，不重复摆放全局版本动作。
- 侧栏按工作区、内容、资源与版本三组组织，标签中英本地化。收起／中等宽度时隐藏分组文字，用间距分隔；窄屏抽屉保留分组标签。账号与退出仍可滚动到达。

## 交互与约束

复用 useStudioWorkspace 的导航、未保存保护、复制、预览和保存路径。新组件只呈现已有工作流状态并发出意图，不引入第二套权限或状态机。模块切换、版本选择、保存失败均不丢失输入。

保留低饱和深色、多主题点缀、图标与少量文字。控件保留可访问名称、键盘操作、44 px 触控目标和减少动态效果支持。吸顶栏不得遮挡浏览器滚动定位后的聚焦控件；窄屏允许版本上下文自然换行，页面不得横向溢出。

## 成功标准

1. 从音乐等任意模块可直接执行当前版本下一步，不必进入历史页找按钮。
2. 历史只读版本、审核通过版本、未保存表单、低权限账号保持原有保护。
3. 桌面和手机长表单滚动后可保存、预览，键盘焦点不被顶栏遮住。
4. 英文和中文分组／动作一致，历史切换、复制、发布监控不退化。

## 非目标

不新增自动保存、批量操作、权限配置、URL 模块路由、发布流程后端改造或编辑器重写，不引入依赖。静态站首页本轮无必要变更。
