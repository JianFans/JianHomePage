# 后台首次使用、身份展示与发布诊断修复

## 设计与约束

- 空内容库恢复成功后提供一份独立于 fixture 的有效初始快照，可直接进入模块编辑。包含遇健我、王子健、现有平台入口与六类板块结构；不自动保存、审核或发布，不覆盖已有版本、未保存内容或只读人员的工作区。不为通过校验伪造音乐作品和媒体元数据。
- 从已验证 OIDC 身份取得用户显示名称、头像，贯穿服务端会话、API 契约与桌面／手机侧栏。保留缺失资料的安全回退，头像只接受安全 HTTP(S) 地址；不以资料接口的角色替代已验证权限。
- 排查 `POST /api/v1/publishes` 返回 404：本地覆盖版本查找、素材校验、快照存储和发布器提交路径，修复已证实缺陷。记录请求 ID、阶段和安全错误分类，区分本站资源不存在与外部存储失败，不输出凭据、令牌、签名 URL 或原始服务商响应。

## 执行顺序

1. 先补失败测试，分别处理初始快照、OIDC 资料、发布错误。
2. 同步生成契约与专项说明；分别运行窄测试，再统一运行受影响门禁。
3. 使用真实浏览器验证首次进入、资料占位和主要编辑交互；独立审查，按职责原子提交到 master，不推送或发布。

## 验证

- Schema、管理端单元测试及类型检查；服务端目标包测试与全包测试、vet、gofmt。
- 修改公开渲染契约时同步生成 TS／Go 类型，验证静态生成和内嵌页面。
- 页面交互运行管理端 E2E；构建仅生成测试所需资源，不生成发布二进制。
- 真实线上发布失败的最终定位以部署后对应请求的日志为证据；本地复现与推断分别说明。
