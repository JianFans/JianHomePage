# 发布反馈与 Toast 实现计划

> 使用 executing-plans 在当前会话顺序实施；用户已授权独立设计和修复。

**目标：** 发布状态可理解、失败可处理，Toast 新消息即时可见且动画不产生滚动条。

**架构：** 复用发布领域服务、持久化 worker、管理端 API 与 Vue 组件；只在云端适配器确定未创建时结束失败任务。发布读取补充安全诊断，恢复继续执行 RBAC、CSRF、锁与审计。

**技术栈：** Go、PostgreSQL、Vue/Nuxt、Vitest、Playwright。

**规格：** [修复设计](../specs/2026-10-20-publish-recovery-toast-design.md)。

## 约束与审查重点

不重试结果不明的创建请求；不因更换配置取消可能存在的部署；旧记录与快照保持不变。轮询迟到响应不能覆盖新任务、退出会话或未保存编辑。恢复表单不接受任意操作者身份。动画离场元素不产生水平滚动。配置和诊断不泄露秘密。
