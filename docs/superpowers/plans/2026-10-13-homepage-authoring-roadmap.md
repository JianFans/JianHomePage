# 下一阶段规划：宣传位、首页编排与视觉预览

> 状态：规划建议，尚未开始实现。
> 基线：主分支 `aadb6c1`，音乐工作台已通过 PR #25 合并。

## 1. 当前能力与下一处断点

管理端已支持素材上传与插入、作品与曲目编辑、音乐板块内编排，以及快照校验、草稿、审核和发布操作。宣传位、其他板块的顺序、启用状态和展示上限仍需手改 JSON；当前预览仅显示 JSON。

下一阶段继续完善内容维护基础能力。优先让编辑人员无需手改 JSON 就能配置首页宣传内容与已有板块，再接入真正的首页视觉预览。

依据：

- [上一阶段路线图](2026-10-10-next-iteration-roadmap.md)。
- [管理端使用说明](../../../apps/admin/README.md)。
- `apps/web/utils/sections.ts`：板块顺序、展示上限和时间过滤。
- `apps/web/pages/index.vue`：首页组件组合、语言、播放器和结构化数据。
- `apps/web/components/home/HeroShowcase.vue`：宣传位媒体、焦点、移动端素材与跳转。
- `packages/schema/schema/content-snapshot.schema.json`：已有宣传位与六类板块契约。

## 2. 方向比较与推荐

| 方向 | 收益 | 代价与边界 |
| --- | --- | --- |
| 宣传位与首页编排，再接视觉预览（推荐） | 承接音乐工作台，先消除手改首页配置的断点；每一步可独立验收 | 分为两个功能分支，第一步仍使用 JSON 预览与可见性摘要 |
| 先做视觉预览 | 立即看见现有快照的首页效果 | 编辑宣传位仍需手改 JSON；需先处理样式、播放器和 Nuxt 依赖隔离 |
| 先做版本列表、比较与身份接入 | 改善多人审核和版本查找 | 涉及服务端接口与身份环境，不能直接补齐首页内容维护能力 |

采用第一种顺序。两个阶段分别设计、实现和审查，避免在一次变更中同时扩展编辑状态机、公共渲染边界和预览通信。

## 3. 阶段 A：宣传位与已有首页板块编排

### 3.1 宣传位表单

- 支持选择、新增、编辑宣传位；已有 ID 不可改名。
- 编辑双语标题、图片／GIF／视频、移动端素材、视频海报、焦点坐标、自动播放标志、关联作品及跳转目标。
- 素材从当前有效快照选择，并按字段用途筛选；素材上传继续通过素材工作台完成。
- 跳转支持无目标、HTTPS 外链及内部内容目标。内部目标提供当前展示状态提示，最终由完整语义校验判定是否可应用。
- 起止时间使用带明确时区的输入与 ISO 8601 序列化；清空可选值时删除对应键，不写空字符串。
- 允许移除宣传位记录及其首页引用，但必须在同一事务中完成，并通过完整校验。不清理其他记录指向该宣传位的引用，不删除媒体对象。
- 展示宣传位顺序在板块条目中维护；记录数组顺序不代表展示顺序。

### 3.2 首页编排

- 支持现有六类板块的上下排序、启用／停用；保持板块 ID、类型和布局变体稳定。
- 支持各板块引用的选择、移除和按位置上下移动；选项只来自对应类型的现有记录。
- 重复引用按引用位置编辑，不自动去重；取消一处引用只移除该处。
- 音乐、影像、现场和片段的展示上限遵循 Schema 各自范围。音乐板块可编辑现有 `moreLink`；其他板块不添加 Schema 未定义字段。
- 宣传位板块保持 1 至 5 个引用，音乐人板块保持至多 1 个引用。停用不绕过 Schema 结构约束。
- 本阶段不新增、删除板块或修改布局变体，避免扩大到公开站重复板块语义与视觉布局重设计。
- 显示「已启用且展示」「已停用」「超出上限」「时间窗口外」等原因，区分配置存在与实际呈现。

### 3.3 事务与状态

`editorText` 继续是唯一可保存内容源。宣传位记录与首页编排组成一个临时草稿，显式应用时原子更新，避免新增宣传位和加入板块之间出现无效中间状态。

打开和应用读取当前文本；应用比较原文本基线，再执行 canonical Schema 和语义校验。失败保留原文、表单和准确诊断路径。改变板块顺序、上限或启用状态导致内部目标不可见时，拒绝应用，不替编辑人员移除跳转。

页面层统一保护音乐草稿、首页草稿与 JSON 的未保存状态。导入、载入、保存、审核和离开页面继续遵守现有确认与忙碌门禁；未应用表单不得被其他工作台或迟到响应覆盖。保存失败、修订冲突和载入失败保留输入。

可见性默认使用快照 `generatedAt`，与当前公开站构建及语义校验保持一致。配置开始／结束时间不代表 EdgeOne 会按时自动重建；本阶段不添加调度发布功能，也不以修改浏览器时钟模拟自动上线。

### 3.4 实施边界与原子拆分

| 职责 | 预期位置 | 验证重点 |
| --- | --- | --- |
| 宣传位与编排原子事务 | `apps/admin/utils/homepage-workbench.ts`、对应单元测试 | 新增与加入同时生效、删除引用、重复条目、合法边界、失败不改原文 |
| 临时草稿与页面交接 | `apps/admin/composables/useHomepageWorkspace.ts`、`apps/admin/pages/index.vue` | 多工作台脏状态、过期基线、确认取消、保存锁、失败恢复 |
| 双语表单与编排组件 | `apps/admin/components`，复用已有双语与平台字段组件 | 时区、素材筛选、按位置排序、键盘操作与窄屏 |
| 浏览器回归与说明 | `apps/admin/test/e2e`、管理端 README | 导入、编辑、应用、导出再导入、冲突与无内容丢失 |

行为实现按 TDD 推进，每个提交只包含一个职责及其测试。具体实现计划在阶段 A 设计确定后编写，本文件不代替逐任务实现计划。

### 3.5 验收标准

1. 从有效快照新增一项宣传内容，绑定已有媒体，配置双语标题、跳转和时间窗口，加入宣传位板块并保存草稿，全程无需手改 JSON。
2. 调整已有板块顺序、启用状态、条目与上限后，导出再导入保持结果和无关内容一致。
3. 重复引用、空板块、宣传位数量边界、跨类型引用、时间窗口、内部目标隐藏均有有意义的回归测试。
4. 音乐与首页工作台切换、JSON 编辑、素材插入、保存冲突和替换快照不会静默丢失临时输入。
5. 桌面、手机和键盘可操作，界面支持中英文；管理端 E2E 与公开站既有 E2E 均通过。

## 4. 阶段 B：复用公开站的视觉预览

阶段 A 稳定后，单独设计和实施视觉预览。

- 预览只接收已经应用且完整有效的快照；不把尚未应用的表单输入误展示为可保存结果。
- 与公开站共用内容解析规则和展示组件。提取显式传入快照与语言的渲染边界，Nuxt 页面继续负责构建数据、SEO 和语言偏好，不复制一套首页模板。
- 默认按 `generatedAt` 展示，支持中英文与桌面／手机视口。未来时间模拟如需增加，应明确标注模拟状态，不能改变快照或冒充发布结果。
- 在独立文档上下文中隔离公开站样式与管理端样式；不把 Token、连接配置或审核状态传入预览。传递数据的通道须在设计中明确并验证边界。
- 未发布快照不得上传到公开预览服务，不写进公开站构建产物或可分享 URL；正式公开站继续只读取构建时快照。
- 默认不自动播放媒体。试听使用预览内单实例播放器，更新快照或关闭预览时释放媒体状态。
- 快照变为无效时清晰提示当前结果已过期，停止将旧画面标记为当前预览。
- 回归检查静态生成、SEO、首屏脚本预算、语言偏好、单实例试听和无障碍，防止共享渲染抽取改变公开站行为。

## 5. 门禁与后续顺序

阶段 A 至少运行管理端单元测试、覆盖率、类型检查、生产构建 E2E，以及 `pnpm lint`、`pnpm test:automation`、`pnpm verify` 和公开站 E2E。阶段 B 涉及共享组件和公开渲染，应重新运行受影响工作区覆盖率、静态产物及完整浏览器门禁。

两阶段均不修改 Go API、数据库或内容 Schema。若实现中发现确实需要修改公共契约，应先独立评估并调整范围。

其后再扩展影像、现场和片段的记录表单，随后规划版本发现、比较与 OIDC 登录。真实 COS／EdgeOne 联调、部署和自动定时发布分别安排，不混入本轮基础能力开发。
