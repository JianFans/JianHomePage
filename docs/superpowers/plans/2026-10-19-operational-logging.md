# 服务端可诊断日志实现计划

**目标：** 用可读、分级、关联完整且可保存转储的日志定位认证、API、存储、发布及启动故障，同时保持外部错误响应与权限行为不变。全部开发与验证在独立工作树中进行，不修改原工作目录。

**架构：** 继续使用标准库 `slog`，新增 `internal/observability` 统一上下文、错误诊断、输出和脱敏。控制台默认 text，可选 JSON；可选 `LOG_FILE` 写独立 JSONL 文件并轮转。生产不增加独立服务或日志查看 API。

**取舍：** 仅改输出格式无法找回丢失的原因；逐处直接打印原始错误会泄漏凭据。采用统一诊断边界，在错误被转换为公开安全信息前记录原因；服务商响应正文、JWT、Cookie、授权码和业务正文不进入日志。

## 配置与行为

- `LOG_LEVEL=info`，允许 debug、info、warn、error；`LOG_FORMAT=text`，允许 text、json。
- `LOG_FILE` 默认关闭；配置文件路径时同步写 JSONL，单文件默认 20 MiB、保留 5 个备份，使用成熟轮转实现。无效配置或文件无法打开时启动失败，运行期写入失败向 stderr 报告，不递归写日志。
- 请求记录 method、匹配路由、状态、耗时、响应字节、请求 ID 和已验证操作者；不记录查询串、原始请求头或正文。健康探针与哈希资源成功请求用 DEBUG；4xx 用 WARN、5xx 用 ERROR。panic 记录代码堆栈并安全返回 500，已提交响应不再写第二个响应。
- 诊断保留错误类型／因果、上下游状态、服务商错误码、数据库 SQLSTATE 与网络超时信息。统一脱敏配置秘密、URL 凭据和查询、常见令牌形式；限制单条错误长度。对可能包含业务数据的服务商与数据库错误只提取诊断字段。
- 认证记录 state／Cookie、兑换、签名、issuer、audience、nonce、角色等失败阶段，不能输出 token 或实际授权码。发布记录任务／版本／构建／部署 ID、状态变化、耗时及恢复动作；云端结果不明不自动重试。

## 执行步骤

1. **已完成：日志基础与诊断。** `internal/observability` 提供分级 text／JSON 控制台、可选轮转 JSONL、上下文 logger、并发输出、错误诊断和统一脱敏。`internal/config` 严格校验日志配置；配置密钥在字段截断前脱敏。
2. **已完成：边界接入。** `internal/auth`、`internal/httpapi`、`internal/publisher`、`internal/publish`、Pages 适配器与 `cmd/api` 已记录认证阶段、HTTP 结果、操作失败阶段及发布生命周期。外部错误只保留白名单错误码、上游状态和校验后的请求 ID；不改变业务状态机及公开响应。
3. **已完成：运维说明与验证。** `.env.example`、`apps/server/README.md` 和 `docs/DEPLOYMENT.md` 已记录配置、输出格式、分级、诊断字段及按请求 ID 查询方法。Go 生成、全包测试、`go vet`、Go 格式、覆盖率、自动化契约和内嵌页面验证均通过；race 检查因环境缺少 CGO 工具链未运行，真实云服务未连接。变更已原子提交在独立工作树；不推送、不部署，保留工作树供后续审查。

## 验收

- 开启文件日志后，可在关闭进程后读取有效 JSONL；轮转上限与备份保留通过测试；失败可见且没有无界日志文件。
- 认证 401、业务 4xx、基础设施 500、panic 和异步发布失败均有可关联的阶段和级别；仅安全分类字段进入日志，响应不泄漏内部错误。
- 脱敏回归覆盖 Cookie、JWT、DSN 密码、客户端密钥、签名 URL 和服务商错误正文；正常网络／数据库／服务商分类仍可读。
- 未访问真实云服务时，只报告本地验证结果，不宣称真实故障已解决。
