# 下一阶段规划：音乐内容结构化编辑

> 状态：第一阶段已完成本地实现与验收，详见 [实现计划与验收记录](2026-10-10-admin-music-workbench.md)。真实云集成与部署尚未验证。
> 基线：主分支 `b06e41c`，已合并素材工作台。

## 1. 规划基线与缺口

规划时，管理端已经支持快照导入导出、共享 Schema 诊断、草稿保存、审核与发布操作，以及素材分页查询、签名上传、完成确认和插入快照。

主要断点在内容编辑：素材插入只追加 `assets`，编辑人员仍需手工维护作品、曲目、素材引用和首页条目。当前「预览」是格式化 JSON，并非实际首页预览。管理端也尚无完整浏览器上传 E2E，已有公开站 Playwright 不能替代该验证。

依据：

- `apps/admin/composables/useAdminWorkspace.ts`：JSON 文本、防抖分析、版本修订与保存。
- `apps/admin/utils/asset-workbench.ts`：素材转换和快照追加。
- `apps/admin/pages/index.vue`：JSON 编辑和预览入口。
- `packages/schema/schema/content-snapshot.schema.json`：作品、曲目、素材和板块契约。
- `packages/schema/src/validate.ts`：跨记录引用、素材类型和内部目标可见性校验。

## 2. 方向比较

| 方向 | 主要收益 | 依赖与范围 | 顺序 |
| --- | --- | --- | --- |
| 音乐作品与曲目表单 | 把已有素材能力用于实际内容维护，减少手改 JSON | 复用现有快照与保存 API，可形成独立闭环 | 第一阶段 |
| 首页编排与实际预览 | 直观看到宣传位、板块顺序和响应式效果 | 需要复用公开站渲染规则，涉及多种内容类型 | 第二阶段 |
| 版本列表、比较与身份接入 | 降低版本查找、审核和登录成本 | 需要进一步梳理 API、认证和部署环境 | 后续独立规划 |

推荐先完成音乐内容结构化编辑。该方向承接素材工作台，也符合既有先完善基础能力、后讨论部署的顺序。

## 3. 第一阶段交付范围

以「从有效快照新增一张作品，配置曲目、封面、平台链接和可选试听，加入音乐板块并保存草稿」为完整使用路径。

### 3.1 作品与曲目

- 作品列表支持选择、新增和编辑，展示封面、标题、类型和曲目数。
- 作品字段覆盖双语标题、单曲／EP／专辑类型、发行日期、封面、平台链接和 `featured`。
- 曲目字段覆盖双语标题、时长、平台链接、署名、可选试听素材和试听时长。
- 同一作品内支持新增、修改、移除和上下移动曲目，维护 `trackIds` 顺序与 `track.releaseId` 归属。
- 保留合法的重复曲目引用及顺序；同一 ID 的字段编辑同步到各引用，移除单次引用不会误删仍被引用的曲目记录。
- 新作品与至少一首曲目一次性应用，避免把只有作品或只有曲目的中间状态写入快照。
- 已有记录 ID 保持稳定；新增 ID 遵循 Schema 前缀并检查冲突。
- 第一阶段不提供作品删除、记录 ID 改名或跨作品迁移曲目。

### 3.2 素材绑定与首页入口

- 封面选择器只显示当前快照中的 `image` 和 `gif` 素材，试听只显示 `audio`。
- 服务端素材需先通过现有素材工作台插入快照，再供表单选择，沿用当前替代文本和权利信息流程。
- 切换封面或移除试听只修改引用，不删除素材库对象或快照素材。
- 允许把作品加入已有音乐板块、移出板块或调整该板块的作品顺序。
- 保留板块中的重复作品引用。排序以首个出现位置为准，跳过相邻相同引用，与最近的不同作品交换；没有目标时禁用按钮。
- 保留板块现有启用状态和 `limit`，明确提示加入条目后是否处于展示范围。
- 没有音乐板块时允许维护作品，提示需配置展示入口；第一阶段不自动创建板块。
- 对导致 hero 或 moment 内部目标不可见、曲目引用缺失等变更，使用完整语义校验阻止应用，不静默清理其他内容的引用。

### 3.3 界面

- 在现有内容区增加音乐编辑入口，保留 JSON 高级编辑和素材工作台。
- 使用紧凑作品列表与编辑区；窄屏改为单列。图标操作提供可访问名称，表单字段保留必要标签。
- 界面文案支持 `zh-CN` 和 `en`；内容字段沿用中文必填、英文可选的契约。
- 不自动播放音频，不在新增表单中另建试听播放器。

## 4. 状态与安全约束

1. `editorText` 继续作为可保存快照的唯一来源。表单允许保留尚未完整的临时输入，但只有显式「应用到快照」成功后才改写文本。
2. 打开表单时同步分析当前文本，不依赖 250 ms 防抖结果。无效 JSON 或无效快照下禁止结构化编辑，保留原文本和现有诊断。
3. 应用时再次同步分析当前文本，并比较打开表单时的文本基线。基线变化则拒绝覆盖，保留表单输入并提示重新载入。
4. 修改副本、同步作品与曲目引用、执行完整 canonical 校验全部成功后，才一次性更新 `editorText`。失败时原文本完全不变。
5. 表单未应用输入、已应用但未保存的快照分别标记。切换作品、载入版本或导入快照前提供明确的继续编辑／放弃入口；离开页面使用浏览器标准未保存提示。
6. 保存期间锁定会改变当前快照和编辑上下文的操作，避免迟到的服务端响应覆盖新输入。保存失败或修订冲突保留本地内容，不自动重试覆盖服务端。
7. 保存仍使用现有版本 API、`If-Match` 和服务端最终校验，不增加第二套作品写入 API。
8. 不增加自动保存、浏览器草稿持久化或 Token 持久化。不得把未发布内容写入公开站构建产物。

## 6. 验收与验证

- 从有效快照完成新增作品、至少一首曲目、封面与可选试听、平台链接、音乐板块编排，整个过程无需手改 JSON。
- 导出后重新导入，作品、曲目顺序、素材引用、双语字段和无关内容保持一致。
- 无效快照、非法日期／链接、错误素材类型、记录 ID 冲突、过期表单和悬空引用均不改写原文本；合法的重复内容引用仍可编辑。
- 表单应用不自动请求 API；保存使用当前内容与当前修订号。服务端冲突不会丢失本地输入。
- 桌面与窄屏可用，键盘可完成主要操作，状态播报不会随每次按键重复触发。
- 为新增函数补充解释约束与失败行为的文档注释，不通过重复代码描述填充文档覆盖率。

## 7. 后续顺序

第一阶段稳定后，再规划 hero 表单与全首页编排，并设计与公开站共用渲染规则的实际预览。随后复用音乐表单中验证过的素材选择、双语字段和事务保护，扩展视频、现场与片段编辑。

完整 OIDC 登录、版本发现与比较、真实 COS／EdgeOne 联调、生产快照和部署演练分别立项。本轮不修改公开内容 Schema、不增加访客登录或论坛，也不改变公开站构建时读取快照的架构。
